agent mode

one persona, one goal, running until it is met or you stop it
Agent mode runs with full autonomy — the same unsandboxed shell and filesystem the CLI has, unattended, in a loop. It stops when it calls mark_done, when it hits the cycle cap, or when you press stop agent.
the goal is the only required field

new project

step 1 of 5 · brief
What are we building?
Name the project and describe the objective. This becomes the brief every agent works from — the orchestrator decomposes it, or you hand pieces out yourself.
Who runs the project?
Either the orchestrator breaks the objective into tasks and delegates them, or you turn it off and assign work to specific agents yourself.
Which model drives it?
8–9B is the sweet spot for reasoning and structured output. Smaller models are faster but weaker at delegation; R1 distills make poor orchestrators — thinking tokens wreck loop latency.
Run it as a pipeline?
Stages run in the order you set, each seeing everything produced above it. Order is meaning — design, then build, then review — and it is also the cost: only one model stays resident, so every change of model between stages costs a reload.
Use a pipeline
Off runs a single agent on the whole brief.
Assign the work
Choose which agents run and what each one is told to do. Blank instructions inherit the project objective.
Ready to launch
Check the brief, then launch. You can end the project any time from the chip in the top bar.
retrieval and mcp are always on — nothing to configure
